# Library compatibility record: generate code + deps -> bundler -> sandbox

A documented, reproducible record of which npm libraries work end to end through the pipeline
`POST /bundle` (the in-Wasm dependency bundler) -> `POST /ts/run` (the ts-sandbox), and why the
rest do not. Covers a broad category sweep plus the most popular / most-downloaded npm packages.

**Result: 253 of 293 libraries pass end to end** (bundle succeeds, the blob runs in the sandbox,
and it produces the expected output). Everything here was produced by actually running each library
through the two real Wasm components over HTTP, not by inspection.

The full row-by-row table with per-library stats is in [REPORT.md](REPORT.md); the raw per-library
data is in `results.json` (regenerated by `run.mjs`).

## Outcomes at a glance

| outcome | count | meaning |
|---|--:|---|
| `pass` | 253 | bundled, ran, produced the expected output |
| `compile_error` | 17 | the sandbox engine rejected the blob at parse time (engine gap) |
| `runtime_error` | 20 | threw while running (engine gap, missing global, or library assumption) |
| `bundle_error` | 3 | too large: the bundler stopped with a clear "dependency graph too large" |

The 40 failures come from a small number of root causes, not 40 independent problems. Details in
[the taxonomy](#failure-taxonomy-every-library-that-does-not-pass-and-why).

## Bundler improvements made from this work

All in `../../src/bundler.ts` and `../../src/shims.ts` (the `ts-sandbox/bundler/` tree is untracked;
`dist/` and `build/` are gitignored, so the component was rebuilt to produce these numbers). Each was found
by the sweep and confirmed by rebuild + re-run, with no regressions.

| fix | what it does | recovered |
|---|---|---|
| `__esModule` writable | esm.sh bundles later do `exports.__esModule = X`; sucrase's prepended non-writable descriptor made that throw in strict mode | validator, handlebars, squirrelly, ajv, tinyduration |
| scan transpiled CJS | scan `require()` in the sucrase output instead of raw ESM, so minified `import*as X from"..."` is not missed and `/node/*.mjs` polyfills get shimmed | ejs, @iarna/toml, yaml, mime-types, form-data |
| Buffer shim upgrade | a `Uint8Array` subclass that adds the Node Buffer API surface (`compare`, `copy`, `equals`, `slice`, `write`, `toString`/`from` for utf8/hex/base64, read/write ints). hex/base64 delegate to the engine's native `Uint8Array.{to,from}Hex`/`{to,from}Base64`, so no conversion code is re-implemented | csv-parse |
| `tty` shim | `tty.isatty()->false` (the engine has no tty; libraries import it for color autodetection) | colorette |
| `path` + `assert` fill-in | `path.relative`/`parse`/`format`; `assert.notStrictEqual`/`throws`/`ifError`/... | yargs |
| large-graph guardrail | per-module + total byte budget; stop before the sucrase pass OOMs the engine and return a clear message | pug, mathjs, marked-terminal now fail cleanly instead of "out of memory" |

Net effect on the original 155-library set: 116 -> 141 passing.

## The engine ceiling: what the bundler cannot fix

The sandbox runs on StarlingMonkey (SpiderMonkey compiled to Wasm). This build is missing some
capabilities; code that needs them fails no matter how it is bundled. Profiled directly against the
running sandbox:

| capability | status | libraries it breaks |
|---|---|---|
| `Intl` (whole object) | **undefined** (no ICU) | `luxon`, `date-fns-tz`, `ow`, `string-length` |
| `String.prototype.normalize` | **missing** | `slugify`, `whatwg-url` |
| `\p{...}` unicode-property regex | **parse error** | the `change-case` family, `marked`, `liquidjs`, `valibot`, `parse-duration`, `humanize-string`, `meow`, `micromark`, `remark-html`, and the ansi-width libs (`string-width`, `wrap-ansi`, `cli-truncate`) |

Present and working, so most modern code is fine: `crypto` (getRandomValues, subtle, randomUUID),
`structuredClone`, `TextEncoder`/`TextDecoder`, `Uint8Array`/`ArrayBuffer`/`DataView`, `Blob`,
`ReadableStream`, `URL`/`URLSearchParams`, `btoa`/`atob`, `BigInt`, `WeakRef`, `FinalizationRegistry`,
`Promise.allSettled`/`any`, regex lookbehind + named groups + `d` flag, `Array.at`/`flatMap`,
`Object.hasOwn`/`groupBy`, `replaceAll`, `queueMicrotask`, `setTimeout`, `fetch`. Notably the engine
ships the TC39 `Uint8Array.{to,from}Hex` / `{to,from}Base64` methods.

Globals: `process`, `Buffer`, `window`, `self`, `navigator`, `global` are all **undefined**.
StarlingMonkey is a web-platform (WinterCG) runtime; its builtins live under `builtins/web/` and it
provides no Node `Buffer` global or `node:` modules. The Node builtins the bundler shims (`buffer`,
`path`, `assert`, `tty`, `events`, `util`, `stream`, ...) are therefore genuine gaps, not
duplicates: they are only module shims (activated when a bundled dependency `require`s them) and are
built on top of the engine's real primitives (the Buffer shim wraps `Uint8Array` + the native
base64/hex methods above). `error.stack` omits the message, which is why the harness wraps code to
recover real error text.

The single highest-impact change would be building SpiderMonkey with unicode-property regex tables:
that one gap is 17 of the 40 remaining failures.

## Failure taxonomy: every library that does not pass, and why

### Engine gap: `\p{...}` unicode-property regex -> `compile_error` (17)

Not fixable in the bundler; esbuild/esm.sh cannot downlevel these escapes at any target.
`marked`, `camelcase`, `decamelize`, `change-case`, `title-case`, `snake-case`, `param-case`,
`liquidjs`, `valibot`, `parse-duration`, `humanize-string`, `meow`, `micromark`, `remark-html`,
`string-width`, `wrap-ansi`, `cli-truncate`.

Verified working substitutes: `voca` / `no-case@3` (case), `micromustache`/`eta`/`handlebars`
(templating), `superstruct`/`zod` (validation), `markdown-it` (markdown), `commander`/`minimist`
(CLI, no ansi-width dep).

### Engine gap: `Intl` undefined / `String.normalize` missing -> `runtime_error` (6)

`luxon`, `date-fns-tz`, `ow`, `string-length` (Intl); `slugify`, `whatwg-url` (normalize).
Substitutes: `dayjs` / `date-fns` (built in), `url-parse`, `query-string`.

### CommonJS circular-dependency init order -> `runtime_error` (3)

`sha.js`, `jws`, `jsonwebtoken` throw `X.prototype is not an object`: a circular `require` returns a
still-incomplete module (a subclass's superclass is undefined at class-eval time). This is inherent
CJS cycle behavior that esm.sh's bundling ordering exposes here. Substitutes: `crypto.subtle` (the
engine has real WebCrypto), `jose` if it bundles, `object-hash`/`crc-32`/`murmurhash`/`hash-sum`.

### Missing global / env detection -> `runtime_error` (4)

`js-sha256`, `js-md5`, `js-sha1` probe a global root object the sandbox does not expose;
`supports-color` references `navigator`. Low value to chase (all have alternatives above).

### Needs a real DOM or a real Node environment -> `runtime_error` (5)

`turndown`, `react-dom` (need a DOM / document), `art-template` (wants `fs`), `is-my-json-valid`
(`Function()` codegen the parser rejects), `xml2js` (`sax` `this`-binding).

### Bundler edge / interop -> `runtime_error` (2)

`node-fetch` (`util` interop returns null under a cycle), `merge-deep` (esm.sh externalized its
`kind-of` dep instead of inlining it, so a bare `require('kind-of')` has nothing to resolve to).

### Too large -> `bundle_error` (3)

`pug`, `mathjs`, `marked-terminal` exceed the per-module / total byte budget and are rejected with a
clear message. Smaller equivalents pass (`micromustache`, `expr-eval`/`numeral`/`fraction.js`,
`markdown-it`).

### Not a failure: async needs the handler shape

Async libraries (`p-limit`, `p-map`, `p-queue`, `p-retry`, `rxjs`, ...) print nothing in the "main"
top-level shape because a floating promise is not awaited before the sandbox returns. They pass in
the `export default { async fetch() { ... } }` handler shape, which the sandbox awaits. This is a
usage rule, not an incompatibility.

## How it was tested

```
 catalog.mjs (293 libs)                    bundler component            ts-sandbox component
   name+version+source+expect  --POST /bundle-->  { blob, stats }  --POST /ts/run-->  { stdout | error }
                                (esm.sh + sucrase + shims + link)      (sucrase -> AsyncFunction)
```

Each catalog entry imports the library, exercises one well-known API, and prints `OK:<value>`. The
harness bundles it, runs the blob in the sandbox, and classifies the outcome, attributing each
failure to the surface that produced it (bundle vs engine-parse vs runtime). Because SpiderMonkey's
`error.stack` omits the message, the harness wraps the user code in the blob so any synchronous
throw (at module load or in the body) reports its real message.

Files in this directory:

- `run.mjs` - the sweep runner. `--only=a,b`, `--conc=N`, `--out=`, `--report=`.
- `catalog.mjs` - the 293-library catalog (seed + two verified fan-out sweeps, deduped by name).
- `REPORT.md` - the generated per-library table; `results.json` - the raw run data.

## How to reproduce

```bash
# 1. build the two components if needed, then start the pipeline
cd wasm/ts-sandbox/bundler/test
spin up -f spin.test.toml --listen 127.0.0.1:3000

# 2. run the full sweep
cd compat
BUNDLER_BASE_URL=http://127.0.0.1:3000 node run.mjs --conc=5    # -> results.json + REPORT.md

# run a subset while iterating
BUNDLER_BASE_URL=http://127.0.0.1:3000 node run.mjs --only=semver,yargs,csv-parse
```

## Remaining recommendations

1. **Engine: add unicode-property regex tables** to the SpiderMonkey build. Highest single win: 17
   libraries, and it removes a footgun for hand-written sandbox code.
2. **Circular-dependency init order** in the linker (would recover `jsonwebtoken`, `jws`, `sha.js`):
   the blob's `__require` caches `module.exports` before running the factory, so a default export
   assigned at the end of a cycle is undefined when a dependent reads it. Matching Node's live-binding
   behavior more closely is the fix, but it is nontrivial.
3. **Inline esm.sh-externalized deps** (`merge-deep` -> `kind-of`): when a fetched module `require()`s
   a bare package esm.sh did not inline, resolve it through `esmUrl` and add it, instead of leaving it
   to the host.
4. The buffer/path/assert/tty shims are complete enough for the common cases; extend `../../src/shims.ts`
   further only as new gaps show up in the sweep.
