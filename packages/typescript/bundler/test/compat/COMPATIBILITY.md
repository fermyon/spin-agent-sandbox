# Library compatibility record: generate code + deps -> bundler -> sandbox

A documented, reproducible record of which npm libraries work end to end through the
pipeline `POST /bundle` (the in-Wasm dependency bundler) -> `POST /ts/run` (the
ts-sandbox), and why the rest do not. Covers a broad category sweep, the most popular /
most-downloaded npm packages, and the Cloudflare-Workers / edge ecosystem (this sandbox
is a WinterCG runtime much like Workers).

**Result: 477 of 571 libraries pass end to end** (bundle succeeds, the blob runs in the
sandbox, and it produces the expected output). Everything here was produced by actually
running each library through the two real Wasm components over HTTP, not by inspection.

The full row-by-row table with per-library stats is in [REPORT.md](REPORT.md); the raw
per-library data is in `results.json` (regenerated by `run.mjs`).

## Outcomes at a glance

| outcome | count | meaning |
|---|--:|---|
| `pass` | 477 | bundled, ran, produced the expected output |
| `runtime_error` | 48 | threw while running (engine gap, missing global, or library assumption) |
| `compile_error` | 29 | the sandbox engine rejected the blob at parse time (engine gap) |
| `bundle_error` | 16 | too large: the bundler stopped with a clear "dependency graph too large" |
| `wrong_output` | 1 | ran cleanly but produced an unexpected value |

The 94 failures come from a small number of root causes.
Details in
[the taxonomy](#failure-taxonomy-every-library-that-does-not-pass-and-why).

There is no longer any `sandbox_crash` or `transpile_err` outcome: the sandbox's
skip-transpile change (below) lets the 128 MB sandbox run the large blobs (`resend`,
`@react-email/render`, `text-encoding`, `elysia`) that used to trap it, so those now
pass. The one exception, `@graphql-tools/schema`, still bundles and runs but throws at
runtime (counted under `runtime_error`).

## Bundler + sandbox improvements made from this work

All in `../../src/bundler.ts` / `../../src/shims.ts` (the bundler) and
`../../../sandbox/src/index.ts` (the sandbox runner). Each was found by the sweep and confirmed
by rebuild + re-run, with no regressions.

| fix | what it does | recovered |
|---|---|---|
| `__esModule` writable | esm.sh bundles later do `exports.__esModule = X`; sucrase's prepended non-writable descriptor made that throw in strict mode | validator, handlebars, squirrelly, ajv, tinyduration |
| scan transpiled CJS | scan `require()` in the sucrase output instead of raw ESM, so minified `import*as X from"..."` is not missed and `/node/*.mjs` polyfills get shimmed | ejs, @iarna/toml, yaml, mime-types, form-data |
| Buffer shim upgrade | a `Uint8Array` subclass that adds the Node Buffer API surface (`compare`, `copy`, `equals`, `slice`, `write`, `toString`/`from` for utf8/hex/base64, read/write ints). hex/base64 delegate to the engine's native `Uint8Array.{to,from}Hex`/`{to,from}Base64`, so no conversion code is re-implemented | csv-parse |
| `tty` shim | `tty.isatty()->false` (the engine has no tty; libraries import it for color autodetection) | colorette |
| `path` + `assert` fill-in | `path.relative`/`parse`/`format`; `assert.notStrictEqual`/`throws`/`ifError`/... | yargs |
| large-graph guardrail | per-module + total byte budget; stop before the sucrase pass OOMs the engine and return a clear message | pug, mathjs, marked-terminal, mysql2, cohere-ai, gpt-tokenizer, ... now fail cleanly instead of "out of memory" |
| `returnawait` repair | sucrase drops the space in `return await obj?.method()` when it rewrites the optional chain into its `_asyncOptionalChain` helper, emitting an invalid `returnawait ...`; restore it in `toCjs` | a correctness fix for any package using that async pattern (found via `resend`) |
| skip-transpile (sandbox) | the bundler prepends a `//__spin_bundled_cjs__` marker; the sandbox recognizes it and skips its own sucrase re-parse of the already-CJS blob, going straight to `new AsyncFunction`. The native parser builds bytecode, not a JS-object AST, so it avoids the engine's GC-object heap cap on big blobs | resend, @react-email/render, text-encoding, elysia (the four former crashes) |
| awaited async blob wrapper | the blob wraps user code in `await (async function(){ ... })(...)` instead of a plain IIFE, so top-level `await` in user source is valid and the sandbox waits for the user's async work before capturing stdout | correctness fix: top-level `await` on the bundler path (was a compile error), and async results no longer cut off |

Net effect on the original 155-library set: 116 -> 141 passing.

## The engine ceiling: what the bundler cannot fix

The sandbox runs on StarlingMonkey (SpiderMonkey compiled to Wasm). This build is
missing some capabilities; code that needs them fails no matter how it is bundled.
Profiled directly against the running sandbox:

| capability | status | libraries it breaks |
|---|---|---|
| `Intl` (whole object) | undefined (no ICU) | `luxon`, `date-fns-tz`, `ow`, `string-length`, `cron-parser`, `@sindresorhus/is`, `temporal-polyfill`, `@formkit/tempo`, `@date-fns/utc` |
| `String.prototype.normalize` | missing | `slugify`, `whatwg-url` |
| `\p{...}` unicode-property regex | parse error | the `change-case` family, `marked`, `liquidjs`, `valibot`, `parse-duration`, `humanize-string`, `meow`, the ansi-width libs (`string-width`/`wrap-ansi`/`cli-truncate`), `path-to-regexp@8`, `zod-validation-error`, `gpt-3-encoder`, `@js-temporal/polyfill`, and the entire `unified`/`remark`/`micromark` markdown-AST stack (`micromark`, `remark-parse`/`stringify`/`gfm`/`rehype`/`html`, `rehype-stringify`/`raw`, `mdast-util-*`) |
| `crypto.subtle` HKDF / some algorithms | not implemented | `@panva/hkdf`, `iron-webcrypto` (`NotSupportedError`) |
| WebAssembly-backed / native libs | can't bundle a `.wasm` / native payload this way | `hash-wasm`, `js-tiktoken`/`@dqbd/tiktoken`, `sharp` |

Present and working, so most modern code is fine: `crypto` (getRandomValues, subtle,
randomUUID), `structuredClone`, `TextEncoder`/`TextDecoder`,
`Uint8Array`/`ArrayBuffer`/`DataView`, `Blob`, `ReadableStream`,
`URL`/`URLSearchParams`, `btoa`/`atob`, `BigInt`, `WeakRef`, `FinalizationRegistry`,
`Promise.allSettled`/`any`, regex lookbehind + named groups + `d` flag,
`Array.at`/`flatMap`, `Object.hasOwn`/`groupBy`, `replaceAll`, `queueMicrotask`,
`setTimeout`, `fetch`. Notably the engine ships the TC39 `Uint8Array.{to,from}Hex` /
`{to,from}Base64` methods.

Globals: `process`, `Buffer`, `window`, `self`, `navigator`, `global` are all
undefined. StarlingMonkey is a web-platform (WinterCG) runtime; its builtins live under
`builtins/web/` and it provides no Node `Buffer` global or `node:` modules. The Node
builtins the bundler shims (`buffer`, `path`, `assert`, `tty`, `events`, `util`,
`stream`, ...) are therefore genuine gaps, not duplicates: they are only module shims
(activated when a bundled dependency `require`s them) and are built on top of the
engine's real primitives (the Buffer shim wraps `Uint8Array` + the native base64/hex
methods above). `error.stack` omits the message, which is why the harness wraps code to
recover real error text.

The memory ceiling is the engine's GC object heap (~40-64 MB of small objects), not
host memory (plain `spin up` sets no cap and the instance addresses ~4 GB). A large
minified blob makes sucrase build a ~1M-node JS-object AST that trips this fixed engine
limit, causing a fatal, uncatchable trap. That is why the sandbox now skips its own
transpile of the already-CJS blob (the native parser builds bytecode, no AST), and why
the bundler is the tighter wall: its per-module sucrase still builds an AST, so it caps
a single module at 700 KB. The bundler is trusted build infra, so it can be provisioned
above the 128 MB sandbox (~256 MB via Spin `max_instance_memory`) to reach the largest
libraries. There is no componentize-js knob for the JS heap itself; raising the
fundamental ceiling needs a custom StarlingMonkey build with a larger `JSGC_MAX_BYTES`.

The single highest-impact change would be building SpiderMonkey with unicode-property
regex tables: that one gap is 29 of the 94 remaining failures, and it alone blocks the
whole `remark`/`unified` markdown ecosystem (`markdown-it` is the `\p{}`-free markdown
that works).

## Failure taxonomy: every library that does not pass, and why

### Engine gap: `\p{...}` unicode-property regex -> `compile_error` (29)

Not fixable in the bundler; esbuild/esm.sh cannot downlevel these escapes at any
target. The `change-case` family (`camelcase`, `change-case`, `decamelize`,
`param-case`, `snake-case`, `title-case`), `marked`, `liquidjs`, `valibot`,
`parse-duration`, `humanize-string`, `meow`, the ansi-width libs (`string-width`,
`wrap-ansi`, `cli-truncate`), `path-to-regexp@8`, `zod-validation-error`,
`gpt-3-encoder`, `@js-temporal/polyfill`, and the entire
`unified`/`remark`/`micromark` markdown-AST ecosystem: `micromark`, `remark-parse`,
`remark-stringify`, `remark-gfm`, `remark-rehype`, `remark-html`, `rehype-stringify`,
`rehype-raw`, `mdast-util-from-markdown`, `mdast-util-to-markdown` (`micromark`'s
tokenizer uses `\p{}`, so everything on top of it inherits it).

Verified working substitutes: `voca` / `no-case@3` (case), `micromustache`/`eta`/
`handlebars` (templating), `superstruct`/`zod`/`valita`/`runtypes`/`io-ts`
(validation), `markdown-it` (the `\p{}`-free markdown parser; works), `commander`/
`minimist` (CLI). For edge routing, `path-to-regexp@8` is the only router that fails;
`hono`, `itty-router`, `rou3`, `radix3`, `find-my-way`, `regexparam`, `url-pattern` all
pass.

### Engine gap: `Intl` / `String.normalize` / `crypto.subtle` HKDF / WASM -> `runtime_error` (15)

- **`Intl` undefined (9):** `luxon`, `date-fns-tz`, `ow`, `string-length`,
  `cron-parser`, `@sindresorhus/is`, and the date/Temporal polyfills
  `temporal-polyfill`, `@formkit/tempo`, `@date-fns/utc`. (`@js-temporal/polyfill` is
  instead a `\p{}` compile error, above.)
- **`String.normalize` missing (2):** `slugify`, `whatwg-url`.
- **`crypto.subtle` HKDF not implemented (2):** `@panva/hkdf`, `iron-webcrypto`
  (`NotSupportedError`).
- **WASM / native payload (2):** `hash-wasm` (ships a `.wasm` that can't be bundled
  this way), `sharp` (a native addon: "Could not load the sharp module using the
  wasi-wasm32 runtime").

Substitutes: `dayjs`/`date-fns` (built in), `url-parse`, `@noble/hashes` +
`@tsndr/cloudflare-worker-jwt`.

### CommonJS circular-dependency / undefined superclass -> `runtime_error` (6)

`sha.js`, `jws`, `jsonwebtoken`, `content-disposition`, `grant`, `pngjs` throw
`X.prototype is not an object`: a circular `require` (or an esm.sh-externalized
dependency) returns a still-incomplete module, so a subclass's superclass is undefined
at class-eval / `inherits()` time. This is inherent CJS cycle behavior that esm.sh's
bundling ordering exposes here. Substitutes: `crypto.subtle` and the `@noble/*` family
(all pass), `jose` (passes), `object-hash`/`crc-32`/`murmurhash`/`hash-sum`.

### Missing global / env detection -> `runtime_error` (5)

`js-sha256`, `js-md5`, `js-sha1` probe a global root object the sandbox does not expose
(then call `Buffer.from` on `undefined`); `supports-color` references `navigator`;
`mailgun.js` expects an AMD `define`. All have alternatives.

### Needs a real DOM -> `runtime_error` (4)

`turndown`, `react-dom`, `juice`, `juice-11-note` need a `document` / DOM the sandbox
does not provide (`createDocument` / `Document is not a constructor`, or React's
minified "objects are not valid as a child" error when there is nothing to render
into).

### Node-internal / interop / library-specific -> `runtime_error` (18)

Reach a Node builtin/internal the shims do not fully cover, an externalized dependency,
or a library-specific assumption:

- **Node `crypto` / `Buffer` internals (7):** `cookie-signature`/`jwt-simple`
  (`createHmac`), `etag` (`createHash`), `fast-jwt` (`crypto.constants`),
  `msgpackr`/`png-js`/`file-type` (`Buffer` internals like `utf8Write`).
- **Externalized / unresolved module (3):** `merge-deep` (esm.sh externalized
  `kind-of`), `dayjs-plugin-relativeTime` (the sandbox's built-in `dayjs` does not ship
  the plugin subpath), `node-fetch` (a `util` cycle: `promisify` on a null module).
- **Library-specific quirks (8):** `arktype` (`type.call` not a function),
  `computed-types` (validation mismatch), `ajv-errors` / `is-my-json-valid`
  (`Function()` codegen the parser rejects), `hyperid` (incomplete base64 chunk),
  `art-template` (wants `fs`), `xml2js` (`sax` `this`-binding),
  `@graphql-tools/schema` (throws inside its precompiled bundle at runtime; it bundles
  and runs now, but the library itself throws).

Several of these are cheap shim top-ups (see recommendation 5).

### Too large -> `bundle_error` (16)

Rejected by the bundler's byte budget (a single oversized minified module OOMs the
bundler's own sucrase pass, or an esm.sh sub-fetch fails): `pug`, `mathjs`,
`marked-terminal`, `mysql2`, `cohere-ai`, `@mistralai/mistralai`, `gpt-tokenizer`,
`js-tiktoken` (5.5 MB), `effect`, `html-minifier-terser`, `jsx-email` (9.9 MB); plus
`image-size`, `thumbhash` (a parse edge case), `htmlnano`, `mjml-core`, `tinytime` (an
esm.sh sub-fetch 404/500). Smaller equivalents pass (`hono`/`h3` for frameworks,
`micromustache`, `markdown-it`, `graphql` core, `@msgpack/msgpack`). The bundler is the
memory wall here; provisioning it above 128 MB (it is trusted build infra) would
recover several of these.

### wrong_output (1)

`zod-to-json-schema` returns a value the snippet did not expect (`OK:false`); likely a
snippet assertion detail rather than a real incompatibility.

### Not a failure: async and top-level `await`

Top-level `await` works on the bundler path (the bundler wraps user code in an awaited
async IIFE, and the sandbox runs the blob as its `AsyncFunction` body), so
`const r = await lib.doAsync(); console.log(r)` prints correctly, with or without
`dependencies`. What still prints nothing is a floating promise
(`(async () => { ... })()` that nobody awaits): standard JS discards it before the run
ends. So await the async call (or use the `export default { async fetch() { ... } }`
handler shape, which the sandbox also awaits). Catalog entries for
`p-limit`/`p-map`/`p-queue`/`p-retry` use the handler shape; they would work equally
with a top-level `await`.

## How it was tested

```
 catalog.mjs (571 libs)                    bundler component            ts-sandbox component
   name+version+source+expect  --POST /bundle-->  { blob, stats }  --POST /ts/run-->  { stdout | error }
                                (esm.sh + sucrase + shims + link)      (AsyncFunction; skip-transpile)
```

Each catalog entry imports the library, exercises one well-known API, and prints
`OK:<value>`. The harness bundles it, runs the blob in the sandbox, and classifies the
outcome, attributing each failure to the surface that produced it (bundle vs
engine-parse vs runtime). Because SpiderMonkey's `error.stack` omits the message, the
harness wraps the user code in the blob so any synchronous or async throw (at module
load or in the body) reports its real message.

Files in this directory:

- `run.mjs` - the sweep runner. `--only=a,b`, `--conc=N`, `--out=`, `--report=`.
- `catalog.mjs` - the 571-library catalog (seed + verified fan-out sweeps across broad
  categories, the most-popular npm packages, and the Cloudflare-Workers ecosystem,
  deduped by name).
- `REPORT.md` - the generated per-library table; `results.json` - the raw run data.

```bash
# 1. build the two components if needed, then start the pipeline
cd packages/typescript/bundler/test

# 2. run the full sweep
cd compat

```

## Remaining recommendations

1. **Engine: add unicode-property regex tables** to the SpiderMonkey build. Highest
   single win: 29 libraries (every `compile_error`), and it removes a footgun for
   hand-written sandbox code.
2. **Provision the bundler above 128 MB** (~256 MB). It is trusted build infra with no
   untrusted execution; its per-module sucrase is now the memory wall, so more headroom
   recovers several of the 16 `bundle_error` libraries (`pug`, `mathjs`, `mysql2`,
   ...).
3. **Circular-dependency init order** in the linker (would recover `jsonwebtoken`,
   `jws`, `sha.js`, `content-disposition`, `grant`, `pngjs`): the blob's `__require`
   caches `module.exports` before running the factory, so a default export assigned at
   the end of a cycle is undefined when a dependent reads it. Matching Node's
   live-binding behavior more closely is the fix, but it is nontrivial.
4. **Inline esm.sh-externalized deps** (`merge-deep` -> `kind-of`): when a fetched
   module `require()`s a bare package esm.sh did not inline, resolve it through
   `esmUrl` and add it, instead of leaving it to the host.
5. **Small shim top-ups** for cheap wins found in the Workers sweep: `crypto.constants`
   (recovers `fast-jwt`), `Buffer.prototype.utf8Write`/`latin1Write` (recovers
   `msgpackr`), and a minimal AMD `define` (recovers `mailgun.js` and other UMD
   bundles).
6. The buffer/path/assert/tty shims are complete enough for the common cases; extend
   `../../src/shims.ts` further only as new gaps show up in the sweep.
