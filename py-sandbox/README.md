# py-sandbox

The Python component of Spin Sandbox. It executes untrusted, AI-generated
Python received as a JSON envelope on `POST /py/...`, compiled to WebAssembly with
[`componentize-py`](https://pypi.org/project/componentize-py/) (CPython 3.12 to
`wasm32-wasi`, Spin Python SDK 3.4.1 for Spin 3.x / WASI Preview 2).

See the [top-level README](../README.md) for the request/response contract, the
security model, and the full list of pre-installed dependencies.

## Build

```bash
bash build.sh            # or, from the repo root: spin up --build
```

`build.sh` creates an isolated python3.12 venv with the pinned build tools
(`componentize-py`; see `requirements.txt`), populates `vendor/` with the runtime
dependencies (including `spin-sdk`) via `setup-vendor.sh`, then runs `componentize-py`
to produce `py-sandbox.wasm`.

The build needs **exactly Python 3.12**: `componentize-py` embeds CPython 3.12 and the
prebuilt packages in `wasi-deps/` are `cpython-312`. `build.sh` looks for `python3.12`
(including the Homebrew locations) and fails with a clear error if it only finds
another version. To use a specific interpreter, run
`PYTHON=/path/to/python3.12 bash build.sh`.

`vendor/` and `.venv/` are git-ignored and fully regenerated by the build. The build
recreates `.venv/` if it runs a different Python or `requirements.txt` changed. It
rebuilds `vendor/` if the Python version, `vendor-requirements.txt`, or
`setup-vendor.sh` changed.
`setup-vendor.sh` copies the prebuilt `wasm32-wasi` packages committed in
[`wasi-deps/`](wasi-deps/README.md) and pip-installs the pure-python deps from
`vendor-requirements.txt`. Override the location with `SPIN_PYTHON_DEPS` if needed.
